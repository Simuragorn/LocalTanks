# Документация LocalTanks

Этот файл — точка входа для человека и нового агента. Не начинайте с чтения всех документов подряд: часть файлов является историей спринтов, а часть генерируется из данных.

## Что читать перед работой

1. `../AGENTS.md` — обязательные правила репозитория, запуск Unity и границы локальных материалов WoT.
2. `../Automation/README.md` — единственный каталог скиллов и конвейеров и порядок их использования.
3. `../PROJECT_PLAN.md` — долгосрочный игровой контракт и этапы.
4. `STATUS.md` — короткий снимок того, что работает сейчас, текущие проверки и следующий пакет.
5. `BACKLOG.md` — только незакрытая очередь.
6. Документ нужной подсистемы из таблицы ниже.

История реализации не хранится в `STATUS.md`: она находится в `CHANGELOG.md` и Git. Старые планы спринтов описывают контекст принятых решений, но не переопределяют текущий код, схемы или статус.

## Генерируемые документы

Эти файлы нельзя править вручную:

- `TANK_BALANCE.md` — сравнение актуальных игровых JSON; создаёт Unity-импортёр.
- `WOT_TOP_CONFIG_SNAPSHOT.md` — профиль топовых модулей локального клиента; создаёт `WoTDataPipeline`.
- `MAP_TACTICS.md` — описание направлений карты; создаёт анализатор карты.

Если производный документ неверен, исправляется его источник или генератор, после чего документ пересобирается.

## Активные и исторические планы

- `SPRINT_010.md` — активный план исполнения; закрыты P0–P5, следующий пакет P6.
- `SPRINT_009.md` — требования к текущему блоку боевого интерфейса и прицеливания.
- `QUICK_COMMANDS_PLAN.md` — отложенный блок чата, паузы, быстрых команд и колеса команд.
- `SPRINT_001.md`–`SPRINT_008.md` — исторические планы. Их числа, пути и формулировки могут быть устаревшими; фактическое состояние берётся из кода, текущих схем, `STATUS.md` и решений ADR.
- `AI_ROADMAP.md` — глобальный порядок развития ИИ после Sprint 010; `AI_TACTICAL_COMBAT_PLAN.md`, `AI_TESTING.md`, `AI_DUEL_LAB.md`, `AI_SQUAD_LAB.md`, `AI_PLAYER_TEST_LAB.md` описывают уже существующую тактику и контур проверок; подтверждённые дефекты сведены в `KNOWN_ISSUES.md`.

## Повторяемые конвейеры

Вся повторяемая автоматизация проекта находится под единым корнем `../Automation/`: реализация конвейеров — в `pipelines/`, инструкции для агента — в `skills/`. Скилл оркестрирует конвейер, но не дублирует его код. Общие инструменты Unity, локальной LLM и документации остаются в `Tools/` и описаны в [`Automation/README.md`](../Automation/README.md).

### Контракт передачи новому ИИ

1. Определи задачу по таблице ниже и открой соответствующий `Automation/skills/<имя>/SKILL.md` целиком до любых изменений проекта.
2. Считай исполняемые файлы в указанном `Automation/pipelines/<имя>/` единственной реализацией процедуры; не восстанавливай команды по истории чата или старому документу.
3. Не используй одноимённые скиллы из пользовательских каталогов Codex, DeepSeek или другого агента и не синхронизируй проект из них.
4. Если процедура изменилась, обнови скилл, конвейер и документацию одним тематическим коммитом.
5. Перед передачей следующему агенту запусти `Tools/Docs/Test-ProjectDocumentation.ps1`: проверка отклоняет отсутствующие связи и возвращение старых каталогов.

| Результат | Конвейер | Скилл |
|---|---|---|
| Топовый спрайт корпуса/башни | `Automation/pipelines/WoTSpritePipeline` | `render-wot-tank-sprite` |
| Полная интеграция машины | несколько конвейеров + Unity importer | `add-localtanks-tank` |
| Боевые параметры топовой конфигурации | `Automation/pipelines/WoTDataPipeline` | `sync-wot-vehicle-data` |
| Звуки машины, карты и экипажа | `Automation/pipelines/WoTAudioPipeline` | `wot-tank-audio` |
| Ортографические объекты и детальная земля | `Automation/pipelines/WoTEnvironmentPipeline` | `build-wot-environment-library` |
| Семантическая карта и AI-сетка | `Automation/pipelines/WoTMapPrimitivePipeline` | `convert-wot-map-to-primitives` |

Локальные производные материалы WoT находятся только в `Assets/LocalOnly` и `LocalData`, игнорируются Git и не публикуются.

## Обновление документации после задачи

- Изменить `STATUS.md`, если поменялось текущее состояние или ближайший шаг.
- Удалить закрытый пункт из `BACKLOG.md`.
- Добавить краткую запись в начало `CHANGELOG.md` с выполненными проверками.
- Добавить ADR только для нового нетривиального решения.
- Добавить запись в `KNOWN_ISSUES.md` только для воспроизводимой незакрытой проблемы.
- Обновить скилл и README соответствующего конвейера в том же коммите, если изменился повторяемый процесс.

После правок документации или скиллов запустить:

```powershell
& .\Tools\Docs\Test-ProjectDocumentation.ps1
```

Проверка не запускает Unity: она сверяет обязательные документы, размер рабочего статуса, frontmatter и имена репозиторных скиллов, наличие README конвейеров и локальные Markdown-ссылки.
