# Визуальный стандарт интерфейса LocalTanks

Назначение этого документа — удерживать единый строгий и читаемый стиль при добавлении новых экранов. Эталон направления — панель настройки звука: спокойный тёмный фон, ясная иерархия, ровные интервалы и цвет только там, где он сообщает смысл.

## Основной принцип

Интерфейс не соревнуется с полем боя. Нейтральные элементы используют тёмные графитово-зелёные поверхности и тёплый светлый текст. Насыщенный цвет зарезервирован для игровых значений: союзник, противник, урон, предупреждение, захват или активное состояние.

Новый игрок должен сначала увидеть главное значение и действие, затем подпись, затем пояснение. Декоративный элемент, не помогающий этой последовательности, не добавляется.

## Технический контракт

- Игровые экраны создаются на UI Toolkit. IMGUI допускается только для существующей разработки и диагностики; новый игроко-ориентированный экран на IMGUI не добавляется.
- Общая тема находится в `Assets/Game/UI/LocalTanksTheme.uss`. Каждый компонентный `.uss` в `Assets/Game/UI` первой директивой импортирует её: `@import url("LocalTanksTheme.uss");`.
- Общие свойства набираются семантическими классами `lt-*`; экранный класс отвечает только за размещение и уникальное состояние. Например: `class="pause-panel lt-panel lt-panel--solid"`.
- `UiStyleContractTests` проверяет существование базовых классов, импорт темы каждым компонентным стилем и применение темы на основных экранах.

## Доступные строительные блоки

| Класс | Назначение |
|---|---|
| `lt-panel` | Базовая тёмная поверхность, тонкая рамка, малый радиус |
| `lt-panel--solid` | Модальное окно с почти непрозрачным фоном |
| `lt-panel--quiet` | Компактный HUD-блок поверх боя |
| `lt-title` | Заголовок окна первого уровня |
| `lt-section-title` | Короткий заголовок группы |
| `lt-label` | Основная подпись поля или строки |
| `lt-caption` | Пояснение и вторичная информация |
| `lt-value` | Число или короткое состояние, которое нужно быстро считать |
| `lt-divider` | Тихий разделитель групп |
| `lt-meter-track` | Общая основа шкал здоровья, захвата и прогресса |
| `lt-button` | Обычная кнопка со всеми интерактивными состояниями |
| `lt-button--primary` | Единственное предпочтительное действие в группе |

Если двух экранам нужен одинаковый новый приём, он сначала добавляется в общую тему как семантический класс. Копирование набора цветов и рамок между `.uss` запрещено.

## Палитра и смысл цвета

- Фон окна: почти непрозрачный графитово-зелёный; HUD-блок — немного прозрачнее, но текстура карты не должна просвечивать сквозь текст.
- Основной текст: мягкий белый, не чистый `#ffffff`. Вторичный текст заметно тише, но остаётся читаемым.
- Акцент интерфейса: приглушённый серо-зелёный. На одном экране достаточно одного основного акцента.
- Зелёный и красный команды, голубой дружественного урона, красный вражеского урона и янтарный предупреждения являются семантическими исключениями. Их нельзя использовать как простое украшение.
- Новое произвольное значение цвета в компонентном `.uss` требует объяснимого игрового смысла. Поверхности, рамки, обычный текст и кнопки берутся из темы.

## Геометрия и типографика

- Базовый шаг отступов — 4 px. Предпочтительные значения: 4, 8, 12, 16, 24 px.
- Радиус малый: 1–3 px для шкал и панелей. Сильно округлённые «карточки» не используются.
- Рамка — 1 px; более толстая сторона допустима как один спокойный акцент или признак команды.
- Минимальная высота интерактивного элемента — 34 px. Между соседними действиями оставляется не меньше 8 px.
- Обычная подпись — 14 px, пояснение — не меньше 12 px, заголовок окна — 20 px. Жирность применяется к заголовку, значению и состоянию, а не ко всему тексту.
- Числа выравниваются последовательно и не прыгают при изменении разрядности. Длинная подсказка переносится строками и отделяется от управляющих элементов.

## Компоновка и поведение

- В модальном окне один явный заголовок, логические группы и одна предпочтительная кнопка. Остальные действия визуально вторичны.
- Постоянный HUD занимает края экрана и не закрывает центр боя. Одинаковые блоки используют одинаковую плотность, рамку и фон.
- Состояния `hover`, `active`, `focus` и `disabled` обязательны для нового интерактивного элемента и должны отличаться без резкой смены палитры.
- Цвет не является единственным носителем критического состояния: рядом остаётся число, текст, форма шкалы или положение элемента.
- Модальное окно регистрируется через `ModalUiState`, закрывается клавишей `Esc` и снимает владельца при уничтожении объекта.
- Экран проверяется минимум при 1920×1080 и 1280×720. Текст и кнопки не перекрываются, а панель не выходит за пределы экрана.

## Проверка перед добавлением UI

1. Экран построен на UI Toolkit и его компонентный стиль импортирует общую тему.
2. Панели, текст, значения, шкалы и кнопки набраны существующими `lt-*` классами.
3. У каждого нового цвета есть игровой смысл; нейтральный цвет не продублирован локально.
4. В группе не больше одного предпочтительного действия.
5. Управление читается на двух целевых разрешениях и на реальном фоне карты.
6. Добавлена автоматическая проверка структуры или поведения; если важен внешний вид, сохранён и просмотрен графический кадр.
7. Новое общее решение внесено сюда и в `LocalTanksTheme.uss`, а не оставлено правилом только одного экрана.
