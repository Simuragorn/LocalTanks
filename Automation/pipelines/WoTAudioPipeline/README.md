# WoT audio pipeline

Конвейер извлекает только перечисленные в `audio_clips.json` Wwise-события, декодирует их в WAV и складывает в локальный Unity-каталог `Assets/LocalOnly/Resources/WoTAudio`. Исходные банки, медиаконтейнеры, WAV и manifest игнорируются Git.

## Запуск

```powershell
powershell -ExecutionPolicy Bypass -File Automation/pipelines/WoTAudioPipeline/Scripts/Setup-WoTAudioPipeline.ps1
powershell -ExecutionPolicy Bypass -File Automation/pipelines/WoTAudioPipeline/Scripts/Invoke-WoTAudioPipeline.ps1
```

По умолчанию клиент ожидается в `C:\Games\World_of_Tanks_EU`. Другой путь передаётся через `-WoTRoot`. Обычный повторный запуск использует локальный кэш. `-Force` заново извлекает банки, медиаконтейнеры, TXTP и WAV после изменения привязки.

## Единственный редактируемый каталог

`audio_clips.json` schema 2 хранит и машинные, и универсальные события. Производный `audio_manifest.json` содержит фактический банк, набор медиаконтейнеров, Wwise-событие, число вариантов, относительный путь, размер и SHA-256 каждого WAV.

Основные поля записи:

- `clipId` — стабильный идентификатор;
- `group` — папка назначения; группа `Vehicles` ради совместимости остаётся непосредственно в `Clips`, остальные создают вложенные папки;
- `bank` — логическое имя банка и медианабора;
- `bankEntry` — необязательный точный путь вложенного банка, например `ussr/inbattle_communication_pc.bnk`;
- `mediaBank` — медианабор, когда он отличается от банка события;
- `mediaEntries` — точный список `.pck`, если событие использует несколько контейнеров;
- `mediaEntriesFrom` — ссылка на другую запись с тем же списком контейнеров, чтобы 12 частей музыки не дублировались в JSON;
- `languageId` — внутренний Wwise ID локализованного банка; для стандартного русского экипажа текущего клиента это `3110496415`;
- `variantIndex` — воспроизводимый выбор TXTP-варианта по номеру; для событий без свитча;
- `variantMatch` — выбор варианта по имени значения Wwise-свитча (совпадение с именем файла TXTP). Для события со свитчем объявляется **только** `variantMatch`: номер зависит от порядка файлов, а имя значения — нет. Конвейер требует ровно одного совпадения и печатает список доступных вариантов, если его нет;
- `trimTrailingSilenceDb` — необязательное удаление длинного хвоста почти полной тишины у готового PCM WAV;
- `usage` — назначение (`loop`, `oneShot`, `voice` или `music`).

`wwiser` и `vgmstream` печатают всё, что печатают, в журналы рабочего кэша (`Work/wwiser-<clipId>.log`, `Work/vgmstream-<clipId>.log`, `Work/trim-<clipId>.log`): их болтливость не должна выглядеть как сбой конвейера, а хвост журнала показывается только при настоящей ошибке.

Многотомная музыка извлекается в отдельные кэш-папки и объединяется в общий медианабор NTFS hard link-ами. Поэтому двенадцать `music_interactive_part_*.pck` не создают вторую гигабайтную копию данных.

## Текущая локальная библиотека

```text
Assets/LocalOnly/Resources/WoTAudio/
  Clips/
    <vehicle-clip-id>.wav
    Mines/
      Music/
      Ambience/
    Universal/
      BaseCapture/
      BattleFlow/
      CrewVoice/
        Russian/{Male,Female}/
        German/{Male,Female}/
        British/{Male,Female}/
        French/{Male,Female}/
        American/{Male,Female}/
      QuickCommands/
        Russian/
  audio_manifest.json
```

Каталог содержит 128 зарегистрированных клипов: 13 машинных и 115 универсальных. Для карты извлекаются загрузочная, спокойная и интенсивная музыка, отдельные результаты победы/ничьей/поражения и летняя атмосфера. Универсальный набор включает захват базы, завершение боя уничтожением последней машины и по захвату базы, пять русских быстрых команд и 100 реплик экипажа: десять ролей в пяти языках и двух голосах. Реплики, которых больше нет в каталоге, конвейер удаляет из папки клипов, поэтому локальный кэш не расходится с `audio_clips.json`.

Событие `base_capture_2` намеренно не объявлено как клип: в текущем банке это управляющее событие остановки, и его декодированный результат — секунда цифровой тишины. Управляющие Wwise-события не должны засорять библиотеку фиктивными WAV.

## Реплики экипажа и языки

Реплики экипажа лежат в локализованных банках `audioww/<нация>/voiceover.bnk`, и одна и та же роль в разных языках и голосах — это разные записи. Поэтому clip ID несёт оба суффикса (`crew_not_penetrated_de_female`), а какие именно — решают данные Unity: `Assets/Game/Resources/CrewVoiceProfiles.json` сопоставляет нацию с языком и голосом, а роль — с шаблоном clip ID вида `crew_ricochet_{lang}_{voice}`. Извлечены пять языков в мужском и женском голосе; немецкие машины говорят по-немецки, американские — по-американски, а женский голос включается значением `voice` у нации. Подробности, доказательства и измерения — в `Docs/WOT_CREW_VOICE_LIBRARY.md`.

Пол в банке — не отдельное событие, а **Wwise-свитч** `SWITCH_ext_vo_gender` с двумя значениями: мужская и женская записи одной реплики. Имена значений подтверждены хэшами и лежат в `wwnames.txt`, поэтому `wwiser` печатает ветку в имени TXTP, а `audio_clips.json` выбирает её полем `variantMatch`.

Новый национальный набор добавляется одной командой, а не двадцатью записями вручную: скрипт берёт
шаблоном уже извлечённый набор, проверяет, что банк есть в клиенте, и при желании объявляет язык в
профиле экипажа. Нацию он не привязывает — это игровое решение.

```powershell
# --dry-run печатает двадцать клипов и ничего не пишет
python Automation/pipelines/WoTAudioPipeline/Scripts/add_crew_voice_language.py `
    --language pl --folder Polish --bank-entry poland/voiceover.bnk `
    --language-id 2614272111 --display-name "Польский"
# убрать набор: --language pl --remove (откажется, если на язык указывает нация)
```

Национальные банки клиента делят один и тот же список ролей и один и тот же свитч пола: проверены все
одиннадцать, поэтому добавление любой нации — это данные плюс прогон конвейера. Что ещё лежит в
клиенте (командиры, блогеры, события) и в каком порядке это разбирать, описано в
`Docs/WOT_CREW_VOICE_LIBRARY.md`, раздел «Как добавить ещё одну озвучку»; перечислить банки в любой
момент можно командой `python Automation/pipelines/WoTAudioPipeline/Scripts/inspect_wot_voice.py --show-special`.

### Как найти событие, а не угадать его

Имена Wwise-событий не лежат в банке открытым текстом, поэтому действовать нужно доказательно:

1. собрать имена, которые использует сам клиент, из `res/packages/scripts.pkg` (описания арен и `item_defs/hints/battle_hints.xml` содержат строки вида `vo_armor_not_pierced_by_player`);
2. проверить имя по хэшу: FNV-1 32 бита от имени должен совпасть с `ulID` объекта `CAkEvent` в дампе банка (`wwiser ... -d txt`); так же проверяются имена свитчей — по `ulGroupID` и `ulSwitchID`;
3. добавить подтверждённое имя в `wwnames.txt`, объявить клип в `audio_clips.json` и запустить конвейер.

Шаги 1–2 выполняет `Scripts/inspect_wot_voice.py`: он собирает кандидатов из `scripts.pkg`, читает языковые ID всех наций прямо из заголовков банков, проверяет имена по дампу и заодно отчитывается, какие подсказки из `wwnames.txt` доказаны этим банком, — ничего не меняя.

```powershell
python Automation/pipelines/WoTAudioPipeline/Scripts/inspect_wot_voice.py --dump LocalData/WoTAudioPipeline/Work/Banks/audioww/ussr/banks.txt
```

## Машины и Unity

`Assets/Game/GameData/Definitions/Tanks/*.json` хранит соответствие танка машинным clip ID и индивидуальные volume/pitch. `TankAudioController` загружает их по стабильным идентификаторам. Универсальные и карточные клипы уже подготовлены как ресурсы, но их подключение к музыке, захвату базы и быстрым командам является отдельной runtime-задачей.

После добавления или изменения машинных событий запустите `Local Tanks > Build Combat Assets`. Отсутствие локальных файлов не ломает игру: локальные клипы никогда не записываются GUID-ссылками в коммитимые префабы.

## Проверка

Успешный запуск завершается строкой `Generated <N> local WoT clips` и кодом 0. Затем следует проверить:

1. число записей manifest совпадает с `audio_clips.json` (сейчас 128 из 128);
2. каждый `relativePath` существует и совпадает с SHA-256;
3. в Git нет файлов из `Assets/LocalOnly` и `LocalData`;
4. `-Force` воспроизводимо пересобирает библиотеку после обновления клиента.

Manifest записывается без BOM: его читает Unity как `TextAsset` и разбирает `JsonUtility`.
