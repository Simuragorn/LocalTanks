# LocalTanks — правила работы агента

- Перед крупной задачей прочитай `PROJECT_PLAN.md` и `Docs/STATUS.md`; для текущего спринта прочитай указанный файл в `Docs/`.
- Работай только внутри `C:\UnityProjects\LocalTanks`. Внешние исходники можно читать, но используемые материалы копируй внутрь проекта.
- Не редактируй UnityYAML (`.unity`, `.prefab`, `.asset`, `.meta`) вручную, если действие можно выполнить через Unity Editor API.
- После изменения кода запусти относящиеся к нему тесты и проверь Unity Console.
- После завершённой задачи обнови `Docs/STATUS.md` и `Docs/CHANGELOG.md`.
- Считай автономность и низкую стоимость сопровождения обязательным критерием архитектуры. Для данных и повторяемого контента предпочитай один редактируемый источник истины, автоматическую генерацию производных файлов, валидацию ссылок и тесты на рассинхронизацию. Не создавай вторую вручную поддерживаемую копию данных, если её можно воспроизводимо получить из первой.
- Если новая сущность в будущем потребует одинаковых ручных изменений в нескольких реестрах, сценах или документах, сначала оцени возможность общего реестра, обнаружения по данным или Editor-генератора. Автоматизация не должна скрывать ошибки: добавляй понятную проверку входных данных и диагностическое сообщение.
- Не обновляй Unity и пакеты без отдельного решения в `Docs/DECISIONS.md`.
- Добавляя машину, соблюдай контракт контура корпуса: точки `PolygonCollider2D` задаются в мировых единицах, равных половине прямоугольника спрайта, умноженной на масштаб, а масштаб визуала обязан быть равномерным по обеим осям. Такая ошибка не видна ни компилятору, ни остальным тестам — только на экране, поэтому `Local Tanks > Build Combat Assets` проверяет контур сам, падает с именем машины и печатает размер коллайдера рядом с размером спрайта.
- Повторяемые конвейеры проекта оформлены как навыки в `.dsh/skills/` и загружаются по имени: `add-localtanks-tank` (полная интеграция машины WoT), `render-wot-tank-sprite` (рендер спрайта из локальной 3D-модели), `wot-tank-audio` (локальные звуки Wwise), `sync-wot-vehicle-data` (синхронизация топового профиля из установленного клиента), `build-wot-environment-library` (локальная библиотека объектов и покрытий карты), `convert-wot-map-to-primitives` (семантическая карта и AI-сетка из арены WoT). Перед выполнением такой задачи загрузи навык, а не восстанавливай процедуру по памяти.
- Единственный источник истины для навыков — каталог `.dsh/skills/` этого репозитория. Личные каталоги навыков агентов, включая `C:\Users\<пользователь>\.codex\skills`, не используются: копии навыков проекта там устарели и не должны ни читаться, ни обновляться. Если нужен новый или изменённый навык, правь только версию в репозитории и коммить её вместе с проектом.
- Делай небольшие тематические коммиты. Автор коммитов этого репозитория всегда должен быть `Simuragorn <simuragorn@gmail.com>`.
- Не добавляй в Git каталоги `Library`, `Temp`, `Logs`, `Obj`, `Build` и локальные файлы IDE.

## Запуск Unity: фон, без перехвата фокуса

- **Любой запуск Unity идёт через одну точку входа — `Tools/Unity/Invoke-UnityBackground.ps1`.** Тесты вызывает `Tools/Invoke-LocalTanksTests.ps1`, он только передаёт параметры. Запрещено вызывать `Unity.exe` напрямую, писать свой путь к редактору, копировать аргументы `-batchmode`/`-nographics` или запускать Unity Hub. Выбор редактора, аргументы, очередь, скрытый запуск, журнал и код возврата живут в одном месте.
- **Обычная проверка всегда идёт в Headless (`-batchmode -nographics`)**: компиляция, EditMode и PlayMode тесты, поведение ИИ, симуляции боёв, телеметрия, проверки данных, префабов и конфигурации, сборка ассетов без GPU. Режим по умолчанию — `Auto`, и он выбирает Headless всякий раз, когда результат можно доказать данными, журналом, телеметрией или XML результатов.
- **Графический режим (`Graphical Background`, `-batchmode` без `-nographics`) применяется только там, где без настоящего графического устройства доказательства не существует**: кадр сцены, частицы, материалы, шейдеры, прозрачность, UI, камера, следы, дым и вспышки. Такую операцию нужно пометить `requiresGraphics` в реестре `Tools/Unity/unity-operations.json`; `Auto` включает графику сам.
- **Графический режим не требует подтверждения пользователя.** Не спрашивай разрешения на запуск, не проси «подтвердить визуальную проверку» и не жди, пока кто-то посмотрит на окно. Результат рендера сохраняется в файл (PNG), а агент читает и анализирует этот файл.
- **Запрещено открывать Unity Editor видимым окном ради компиляции и тестов**, выводить его на передний план, сворачивать и разворачивать, а также запускать второй экземпляр для проекта, открытого в редакторе. Если проект уже открыт интерактивно, запускатор сообщает об этом (код возврата 3) и не трогает чужой редактор; продолжай проверки, которым Unity не нужен.
- **Запрещено управлять Unity мышью, клавиатурой или синтетическими нажатиями** без отдельной объективной причины, записанной в `Docs/DECISIONS.md`. Возвращать фокус пользователю имитацией клавиш нельзя ни при каких условиях: если окно всё-таки перехватило фокус, это дефект запускателя, и он исправляется в запускателе.
- **Диагностические изображения сохраняются в проект** (`Docs/Media`, `TestResults`) и анализируются из файла. Не открывай папки, отчёты и картинки автоматически после запуска.
- Несколько агентов могут захотеть запустить Unity одновременно: запускатель ставит их в очередь по именованному мьютексу и пишет владельца в журнал. Никогда не завершай чужой процесс Unity.
