# WoT audio pipeline

Конвейер извлекает только перечисленные в `audio_clips.json` Wwise-события, декодирует их в WAV и складывает в локальный Unity-каталог `Assets/LocalOnly/Resources/WoTAudio`. Исходные банки, медиаконтейнеры, WAV и manifest игнорируются Git.

## Запуск

```powershell
powershell -ExecutionPolicy Bypass -File Tools/WoTAudioPipeline/Scripts/Setup-WoTAudioPipeline.ps1
powershell -ExecutionPolicy Bypass -File Tools/WoTAudioPipeline/Scripts/Invoke-WoTAudioPipeline.ps1
```

По умолчанию клиент ожидается в `C:\Games\World_of_Tanks_EU`. Другой путь передаётся через `-WoTRoot`. Обычный повторный запуск использует локальный кэш. `-Force` заново извлекает банки, медиаконтейнеры, TXTP и WAV после изменения привязки.

## Единственный редактируемый каталог

`audio_clips.json` schema 2 хранит и машинные, и универсальные события. Производный `audio_manifest.json` содержит фактический банк, набор медиаконтейнеров, Wwise-событие, число вариантов, относительный путь, размер и SHA-256 каждого WAV.

Основные поля записи:

- `clipId` — стабильный идентификатор;
- `group` — папка назначения; группа `Vehicles` ради совместимости остаётся непосредственно в `Clips`, остальные создают вложенные папки;
- `bank` — логическое имя банка и медианабора;
- `bankEntry` — необязательный точный путь вложенного банка, например `ussr/inbattle_communication_pc.bnk`;
- `mediaBank` — медианабор, когда он отличается от банка события;
- `mediaEntries` — точный список `.pck`, если событие использует несколько контейнеров;
- `mediaEntriesFrom` — ссылка на другую запись с тем же списком контейнеров, чтобы 12 частей музыки не дублировались в JSON;
- `languageId` — внутренний Wwise ID локализованного банка; для стандартного русского экипажа текущего клиента это `3110496415`;
- `variantIndex` — воспроизводимый выбор TXTP-варианта;
- `trimTrailingSilenceDb` — необязательное удаление длинного хвоста почти полной тишины у готового PCM WAV;
- `usage` — назначение (`loop`, `oneShot`, `voice` или `music`).

Многотомная музыка извлекается в отдельные кэш-папки и объединяется в общий медианабор NTFS hard link-ами. Поэтому двенадцать `music_interactive_part_*.pck` не создают вторую гигабайтную копию данных.

## Текущая локальная библиотека

```text
Assets/LocalOnly/Resources/WoTAudio/
  Clips/
    <vehicle-clip-id>.wav
    Mines/
      Music/
      Ambience/
    Universal/
      BaseCapture/
        Russian/
      BattleFlow/
        Russian/
      QuickCommands/
        Russian/
  audio_manifest.json
```

Каталог содержит 30 зарегистрированных клипов: 13 машинных и 17 универсальных/относящихся к «Рудникам». Для карты извлекаются загрузочная, спокойная и интенсивная музыка, отдельные результаты победы/ничьей/поражения и летняя атмосфера. Универсальный набор включает захват базы, завершение боя уничтожением последней машины, начало боя и русские быстрые команды.

Событие `base_capture_2` намеренно не объявлено как клип: в текущем банке это управляющее событие остановки, и его декодированный результат — секунда цифровой тишины. Управляющие Wwise-события не должны засорять библиотеку фиктивными WAV.

## Машины и Unity

`Assets/Game/GameData/Definitions/Tanks/*.json` хранит соответствие танка машинным clip ID и индивидуальные volume/pitch. `TankAudioController` загружает их по стабильным идентификаторам. Универсальные и карточные клипы уже подготовлены как ресурсы, но их подключение к музыке, захвату базы и быстрым командам является отдельной runtime-задачей.

После добавления или изменения машинных событий запустите `Local Tanks > Build Combat Assets`. Отсутствие локальных файлов не ломает игру: локальные клипы никогда не записываются GUID-ссылками в коммитимые префабы.

## Проверка

Успешный запуск завершается строкой `Generated <N> local WoT clips`. Затем следует проверить:

1. число записей manifest совпадает с `audio_clips.json`;
2. каждый `relativePath` существует и совпадает с SHA-256;
3. в Git нет файлов из `Assets/LocalOnly` и `LocalData`;
4. `-Force` воспроизводимо пересобирает библиотеку после обновления клиента.
